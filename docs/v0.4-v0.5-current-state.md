# v0.4 / v0.5 实施前基线

基线提交：`d108ba5`（2026-08-25）。本文件只描述修改前已经存在的能力。

## 已有能力

- FastAPI + PostgreSQL 模块化单体雏形，数据库迁移由 `app/database.py` 在启动时执行。
- 设备登记、一次性激活、HTTP Bearer 凭证轮换/吊销。
- 设备心跳、能力与库存快照、设备事件 Inbox、命令状态迁移。
- 公开扫码菜单、幂等测试订单、单设备串行制作、设备权威进度和终态。
- MQTT 5.0/TLS 传输验证；终端使用 SQLite Inbox/Outbox；EMQX 禁止匿名并按设备 Topic 设置 ACL。

## 确认存在的缺口

1. `sales_order.payment_mode/payment_status` 只是 `TEST_FREE/NOT_REQUIRED` 占位。订单创建时立即创建 `production_job` 并调用 `dispatch_next_order()`，不存在 Payment、Refund、Callback Inbox 或支付对账。
2. `app/mqtt_gateway.py` 读取单一 `DEVICE_ID/DEVICE_TOKEN`，只能代理一台设备，并通过 HTTP 适配现有设备 API。
3. 云端设备事件只有 HTTP `terminal_event` 去重，没有独立 MQTT Inbox、Topic/载荷身份核对和统一消息处置记录。
4. 命令记录与业务事务在同库，但 MQTT 网关轮询设备 HTTP 命令接口；没有独立 Command Outbox 发布租约、重试计数和 PUBACK 状态。
5. MQTT username/password 由 EMQX 外部脚本维护，尚未与设备激活、轮换、吊销形成同一生命周期。
6. 离线监控只处理连接状态和未送达命令过期；没有 ACK/START/RUNNING watchdog、`HOLD`/人工复核和支付/退款对账。

## 实施边界

- 保留 FastAPI + PostgreSQL 和现有订单/设备领域逻辑，不引入 Kafka、Kubernetes 或 Redis 作为事实源。
- MQTT Gateway 只做传输、协议校验、持久 Inbox/Outbox 驱动；业务状态迁移复用云端领域函数。
- 模拟器只补协议字段与联调能力，不扩展动画或无关 UI。
- 支付宝真实沙箱验收依赖人工提供沙箱 appId、应用私钥、支付宝公钥和可访问回调地址；代码与自动化测试不能伪造这项外部验收。
