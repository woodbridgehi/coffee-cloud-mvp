# v0.4 Payment Domain / v0.5 Device Platform 实施计划

## 交付顺序

1. 新增 Payment、Payment Callback Inbox、Refund、业务 Outbox、MQTT Inbox、Command Outbox、MQTT Credential 数据结构和约束。
2. 实现支付/退款状态机和 `PaymentProvider`；先以 Mock Provider 覆盖重复回调、乱序、金额冲突和重复退款。
3. 实现支付宝统一下单、查询、关闭、退款、RSA2 回调验签；沙箱/生产只通过配置切换。
4. 订单改为 `CREATED → AWAITING_PAYMENT → PAID → QUEUED`；支付成功事务只写 Payment、Order 与 Outbox，不直接发布 MQTT。
5. Worker 消费 Outbox，幂等创建唯一 `production_job`；Command Outbox 独立发布并记录 PUBACK/重试。
6. Gateway 改为通配 Topic 的多设备进程，校验 Topic 与载荷 deviceId，先持久化 MQTT Inbox，再调用共享设备领域服务。
7. 增加 MQTT 凭证元数据、轮换/吊销接口和 Broker Provisioner 抽象；EMQX REST 自动化在配置启用时执行。
8. 增加命令与支付/退款 watchdog、查询对账和 `UNKNOWN/HOLD/manual_review` 处置。
9. 运行纯领域单元测试、PostgreSQL 集成测试、MQTT 协议测试以及 001/002 双设备端到端验证。

## 验收闸门

- 未支付订单没有制作任务和设备命令。
- 同一支付回调重复处理只产生一次 `payment.paid` Outbox 和一个制作任务。
- MQTT QoS 1 重投不会重复迁移状态；旧 revision 不覆盖新状态。
- 命令发布崩溃后可由 Outbox 重试；不确定物理结果进入 `UNKNOWN/HOLD`，不自动退款。
- 退款具有业务幂等键和 provider request id；网络超时先查询原退款，不盲目创建第二笔。
- Gateway 运行配置中不存在单设备 `DEVICE_ID/DEVICE_TOKEN`。
