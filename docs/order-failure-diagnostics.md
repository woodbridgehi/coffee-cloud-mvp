# 订单失败原因与拉花指令兼容（2026-09-11）

## 本次根因

在本地 `coffee-bot-003` 的只读事件记录和指令收件箱中，拉花订单被设备以 `COMPILED_RECIPE_MISMATCH` 拒绝；云端发送了 `bj-latte-v1 / 2.1.0`，但未附带 customization、compiledRecipeDigest、optionSchemaVersion。终端新增定制配方校验后，旧云端基础饮品指令因缺少指纹立即失败。这不是三维动画或拉花轨迹执行失败。

终端兼容完全不带上述三个字段的旧指令，但必须明确匹配已安装配方版本，且默认编译后的步骤、剂量、时长与基础配方相等，价格增量为零。兼容订单使用本地冻结的默认配方，记录 `executionContract=legacy-default`；带任一定制字段的指令仍须通过指纹校验，缺失、篡改或配方版本不符均拒绝。未知配方、库存不足、设备忙碌与取杯位占用仍按原规则处理。失败订单不自动重做。

## 查看错误

- 顾客订单状态页：显示失败原因和错误代码。制作失败后停止倒计时，不把后续里程碑标成完成。退款后仍保留原失败原因。只有 `READY` 且未取走的订单显示取杯口令，失败、排队、制作、取消等状态不显示口令或装饰条码；菜单恢复入口也按当前状态显示，忽略旧缓存里的失败订单口令。
- 设备运营台：订单列表直接显示原因摘要；点击展开可见代码、失败步骤、任务编号、发生时间、排查建议及配方版本/指纹等定位信息。
- 商户后台：订单列表有原因摘要；订单详情增加“失败原因与定位”。沿用原有租户、门店和订单读取权限。

云端复用 `sales_order.failure_code/failure_message` 与 `production_job.failure_json`，无需数据库迁移。拒绝回执先到时就保存原因，重复事件不覆盖已存诊断。旧记录里的“制作失败”或“任务被拒绝：错误代码”在读取时转换为可读说明；完全没有具体原因时明确提示设备未提供原因。顾客接口仅返回代码和说明，后台附带白名单诊断字段，不返回原始命令或凭据。
