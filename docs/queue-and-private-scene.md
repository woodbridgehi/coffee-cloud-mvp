# 同机排队与匿名三维观看

线上支付确认成功后（测试模式接单后），订单及制作任务保存在 PostgreSQL。派单在设备锁内检查当前任务和取杯位，按 `production_job.created_at,id` 依次派送。关掉顾客页面不会取消订单，也无需把多单预先发进机器人缓存。沿用既有库存承诺与队列上限（默认 20，可配置），库存不足或队列满仍拒绝继续接单。

订单状态响应新增 `queue`：`aheadCount` 包含正在执行的任务及更早的排队任务；`estimatedWaitSeconds` 表示预计开始制作前的等待，不包含自己的制作时间。按前方配方计划时长和当前任务剩余时间估算；暂停、重试等待、故障核查、设备离线、待取杯或缺少时长时返回 null。取杯和实际操作可能使预估延长。排队 SSE 每 5 秒刷新队列，避免仅监听自己的订单时漏掉前方变化。

排队页的观看按钮由顾客主动点击。`GET /api/v1/public/orders/{B}/scene` 必须携带 B 自己的 `X-Order-Access-Token`，只允许仍在排队的 B 查看同一台设备当前执行中的动作。响应设为 no-store，仅返回三维必需的语义动作、时长、进度和合成步骤编号；不返回 A 的订单、真实任务编号、商品名、配方名称、原料明细、金额、付款信息、取餐码或访问凭证。匿名场景标识绑定观看者凭证，不能拿来读取源订单。

观看期间每 4 秒刷新一次，关闭、后台、断网或场景不再可用时停止。轮到 B 时关闭旁观，回到 B 自己的三维制作。旁观弹窗隐藏订单、原料和完成信息，也不触发 A 的完成声音。自己的状态页默认嵌入三维，允许切换二维进度；状态更新保留当前选择和三维实例。无有效三维计划或 WebGL 不可用时给出说明，可切回二维。

验证包含真实 PostgreSQL 的 A/B/C/D/E 排队、等待时间、权限隔离、暂停后不可观看、A 完成后先派 B，以及排队 SSE 无自身事件时刷新。Playwright 用模拟 API 在 1280×900、390×900 验证默认三维、二维切换、主动旁观、关闭和轮到自己的状态切换。仍需按实际设备吞吐、取杯时间校准等待预估；本次没有生产压测或部署。
